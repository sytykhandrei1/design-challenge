# PLATA — материалы карты, v1 (archived authoring package)

Три варианта одного дизайна: `brushed-metal`, `matte-plastic`, `glossy-plastic`. Для каждого подготовлены front, back и отдельное edge. Все результаты находятся в этой папке; исходный iOS target, ассеты и поведение приложения не заменены. Коммитов и push нет.

Это исходные PBR-комплекты для интеграции. Их проверили в отдельном нативном SceneKit/Metal-рендерере на Apple M3 Pro. Проверка памяти и производительности на физическом iPhone остаётся этапом интеграции.

## Что брать

| Папка / файл | Назначение |
|---|---|
| `materials/<material>/front/<tier>/` | Лицевая поверхность без изменяемого имени |
| `materials/<material>/back/<tier>/` | Оборот без изменяемых реквизитов и их подписей |
| `materials/<material>/edge/` | Отдельный материал ребра |
| `layers/<material>/<side>/<tier>/` | Изменяемая графика: RGBA, маска покрытия и карты свойств |
| `demo/<material>/<side>/<tier>/` | Собранные примеры с CARD HOLDER, 0000 0000 0000 0000, 00/00, CVC 000 |
| `shared/masks/<tier>/` | Отдельные маски логотипа, чипа, каналов чипа, платёжного знака, NFC, полосы, подписи и каждого поля |
| `shared/vector/` | Масштабируемые SVG: PLATA, NFC, чип, платёжный знак |
| `shared/layout.json` | Координаты элементов в утверждённой системе 1645×956 и шрифты полей |
| `shared/micro/` | Периодические сигналы микрорельефа и промежуточные Height-изображения |
| `manifest.json` | Размеры, физические параметры, диапазон высот, сведения об экспорте |
| `previews/` | Нативные рендеры, сравнения, увеличение 3× и GIF вращения |
| `verification/file-inventory.csv` | Полный перечень файлов, размеров и SHA-256 |
| `verification/checks.json` | Машинный отчёт проверок |
| `sources/` | Копии пяти утверждённых исходников |

`tier` — `standard` (3072×1786) либо `zoom` (6144×3572). Ребро — 2048×64. Обе стороны горизонтальны. Внешний фон, скругление силуэта, тени и блики в PBR-карты не добавлены: силуэт задаётся геометрией.

В каждой поверхности шесть файлов:

| Файл | Формат и смысл |
|---|---|
| `basecolor.png` | RGB8, встроенный sRGB ICC; при семплировании декодировать sRGB в linear |
| `metalness.png` | L8, линейные данные 0…1, использовать R |
| `roughness.png` | L8, линейные данные 0…1, использовать R; это roughness, не glossiness |
| `normal.png` | RGB8, линейные данные; tangent-space OpenGL: +X вправо, +Y вверх по изображению, +Z наружу |
| `normal-scenekit.png` | Та же Normal с G=255−G; проверена с геометрией и UV из приложенного SceneKit-рендерера |
| `height.png` | L16, линейные данные; `height_mm = value/65535 × 0.018 − 0.012` |

Технические PNG намеренно не имеют цветового ICC-профиля. При загрузке явно отключать sRGB. Не применять к ним автоматические цветовые преобразования. Height нужна для авторинга/перекомпоновки: загружать её вместе с готовой Normal в обычном статическом рендере не требуется. Две Normal — альтернативы, одновременно используется только одна.

## Материалы

| Участок | Metalness | Roughness | Рельеф |
|---|---:|---:|---|
| Шлифованный металл | 1 | 0.34 + микровариация | Направленная микрофактура, коэффициент высоты 0.32 мкм |
| Гравировка металла | 1 | 0.62 + микровариация | −4 мкм, без нарисованной тени по краям |
| Матовый пластик | 0 | 0.68 + микровариация | Ненаправленный микрорельеф, коэффициент 0.65 мкм |
| Печать на матовом пластике | 0 | 0.66 | +0.3 мкм |
| Глянцевый пластик и печать | 0 | 0.17 + небольшая микровариация основания | Коэффициент 0.055 мкм; графика под гладким покрытием |
| Контакты чипа | 1 | 0.26 | −1 мкм |
| Изоляционные каналы чипа | 0 | 0.57 | −3 мкм |
| Магнитная полоса | 0 | 0.52 | +1 мкм |
| Область подписи | 0 | 0.84 | +1.5 мкм |

Точные значения и диапазоны — в `manifest.json`. Серебристая основа у всех трёх материалов имеет одинаковый нейтральный Base Color: linear RGB 0.58. Графика металла — 0.21, пластиков — 0.035. Значения металла — художественная модель обработанного серебристого сплава, а не измеренная отражательная способность конкретного металла.

Утверждённые изображения фактур использованы как художественные источники частот и направленности. Из них удалён низкочастотный световой рисунок. Периодический микрорельеф синтезирован по их спектру с фиксированными seed и новым распределением фаз: это устраняет граничные швы, сохраняя характер зерна. Период — 16 мм. Дискретные крайние пиксели не обязаны быть равны: проверяется, что перепад через границу статистически соответствует соседним перепадам внутри фактуры. Проверочные повторения 2×2 находятся в `verification/`.

Normal вычислена из физически заданного Height: `normalize(−dH/dX, +dH/dYimage, 1)`, затем RGB=`normal×0.5+0.5`. Шаг производной учитывает размер карты в миллиметрах. Цветовая яркость полного дизайна не использовалась для автоматического создания Metalness/Roughness.

## Разметка и изменяемые поля

PLATA восстановлена гладкими контурами и кривыми по утверждённому силуэту. Контраст увеличен материалом гравировки; толстых чёрных обводок у надписи нет. Геометрия платёжного знака и чипа восстановлена программно. Загрязнения альфа-канала вокруг полосы подписи удалены.

Слова и числа заново растрируются из шрифтов под целевое разрешение. Имя — Arial Bold; цифры — Avenir Heavy; служебные подписи — Helvetica. Позиции и габариты сопоставлены с утверждённой графикой. **Исходный шрифт не был приложен: точное совпадение начертания нельзя гарантировать.** Это задокументированная реконструкция, а не заявление о наличии оригинального брендового шрифта.

Для live-имени/реквизитов использовать статические `materials/` и отдельные `layers/`, а не `demo/`:

1. Рендерить нужную строку в одноканальную маску по `shared/layout.json` через CoreText/Metal. Для скрытого поля маска равна нулю. Сохранять общее положение и UV.
2. Объединить только нужные маски полей. Графика банка, чип, полоса и NFC при этом не меняются.
3. Смешать Base Color **в linear**, используя straight alpha из `basecolor-rgba.png`. PNG слоя хранит sRGB RGB и отдельное линейное покрытие alpha.
4. Для каждого технического свойства применять `mix(static, override, mask)`. В `layers/` есть `metalness-override.png`, `roughness-override.png`, `height-override.png`.
5. После смешивания Height заново вычислить Normal в изменённой области с соседней полосой минимум 1 пиксель. Не складывать и не альфа-смешивать Normal как обычную RGB-картинку: гравировка должна исчезать вместе с выключенным именем.
6. После изменения обновить mipmaps соответствующих текстур. Перекомпоновку 6K выполнять вне main thread либо GPU-проходом и только по изменённой области.

Все цветовые/технические маски получены из одной разметки. Демонстрационная сборка воспроизводится этим же композитором. Маски полей есть по отдельности, поэтому имя, PAN, срок и CVC можно скрывать независимо.

## Подключение в SceneKit / Metal

Для SceneKit использовать `.physicallyBased`, `diffuse=basecolor`, `metalness=metalness.R`, `roughness=roughness.R`, `normal=normal-scenekit`. В приложенном `RenderMaterials.swift` показана загрузка через `MTKTextureLoader`: `.SRGB=true` только у Base Color, `.SRGB=false` у технических карт; mipmaps, linear filtering, anisotropy 8. Металл должен отражать окружение — для QA приложены два варианта студийного освещения.

Нативная проверка направления Normal сравнивает одинаковый вектор, заданный геометрической нормалью и RGB-текстурой. Результат — `previews/normal-direction-probe.png`; знак G адаптирован именно к предоставленной геометрии/UV. При смене tangent basis в другом рендерере повторить проверку; для стандартного OpenGL tangent space брать `normal.png`.

У тестовой карты три material slots: front, back, edge. Это замкнутая геометрия, а не две совмещённые плоскости. Радиус скругления углов — 10% высоты; ребро имеет округлённый профиль. Размер в QA: 85.6×49.7674×0.7704 мм, профиль скругления ребра 0.10272 мм. Пропорции и толщина масштабированы из фактической модели приложения 100×(100/1.72)×0.9; это **не утверждение о соответствии ISO ID-1**.

UV front: `u=0.5+x/width`, `v=0.5−y/height`. UV back: `u=0.5−x/width`, `v=0.5−y/height`. При повороте на 180° вокруг Y оборот читается слева направо. Edge использует U по периметру и V от front к back; готовый пример геометрии находится в рендерере.

Текущие материалы лицевых сторон приложения используют `.constant` и собственный sheen. Простая замена PNG не подключит эти PBR-свойства. При будущей интеграции потребуется заменить материал на PBR, задать UV ребра вместо постоянных UV и убрать двойное освещение старым эффектом. В этой задаче это намеренно не менялось.

Документация Apple: [physicallyBased](https://developer.apple.com/documentation/scenekit/scnmaterial/lightingmodel-swift.struct/physicallybased), [metalness](https://developer.apple.com/documentation/scenekit/scnmaterial/metalness), [lightingEnvironment](https://developer.apple.com/documentation/scenekit/scnscene/lightingenvironment).

## Разрешение и память

В фактическом коде `CardPhysics.maximumScale=3`; размер preview: `min(height−78, (width−92)×1.72)`. Для экрана шириной 440 pt и scale 3 длинная сторона при максимальном зуме требует примерно 5387 физических пикселей. Поэтому мастер 6144 px даёт запас, а 3072 px подходит для обычного просмотра и промежуточного зума.

Это не апскейл деталей исходного PNG: графика построена заново в целевом разрешении, фактура семплируется с физическим периодом 16 мм. Скрытые детали исходника не «восстанавливались».

Зум-кадры renderer калиброваны под длинную сторону 5387 px при 3×. Каждый файл 1800×1800 показывает выбранную область такой проекции, а не уменьшенную целую карту.

Оценка несжатой GPU-памяти на **одну сторону**: Base Color RGBA8 + Normal RGBA8 + Metalness R8 + Roughness R8, включая mipmaps:

| Размер | Одна сторона | Две стороны |
|---|---:|---:|
| 3072×1786 | около 69.8 MiB | около 139.5 MiB |
| 6144×3572 | около 279.1 MiB | около 558.1 MiB |

Это расчёт, не замер. Если загрузчик развернёт одноканальные PNG в RGBA, расход станет выше. Не загружать все три материала и оба LOD сразу. Практический вариант: один выбранный материал; 3072 для обычного просмотра; 6144 только для видимой стороны при сильном зуме, с освобождением предыдущей версии. Height и промежуточные слои не нужны постоянно в GPU.

Перед включением в продукт: проверить фактический pixelFormat, бюджет iPhone, конвертировать статические карты в подходящий ASTC/Metal-формат и проверить качество сжатия нормалей/тонкой графики. Упаковка Roughness+Metalness уменьшает число texture fetch, но сама по себе не гарантирует меньший объём, чем два R8. GPU-компрессор в этом окружении не найден; поставляются PNG-мастера без заявления о готовом мобильном memory budget.

## Повторить проверку

Из этой папки, Python с numpy/Pillow и системными шрифтами macOS:

```sh
python3 scripts/build_materials.py
python3 scripts/prepare_studio.py
sh scripts/review-materials.sh --normal-probe
sh scripts/review-materials.sh --zoom --spin
python3 scripts/make_previews.py
python3 scripts/verify_materials.py
```

Интерактивный просмотр: `sh scripts/review-materials.sh --interactive`. Мышь — вращение; Shift+drag — перемещение области; pinch/scroll — 1…3×; 1/2/3 — материал; L — освещение; R — сброс. Это отдельный macOS-инструмент, в target Plata он не добавлен.

## Ограничения

- Материалы художественно настроены, а не измерены с физических образцов. Проверочное окружение LDR, без калиброванной HDR-съёмки.
- Направленная шлифовка передана микрорельефом. Стандартный SceneKit PBR в этом примере использует изотропную BRDF; полноценную анизотропную модель при необходимости следует добавить отдельно.
- Перепад цвета на границе графики и ребра допустим: гравировка/печать не продолжается на торец. Микрофактуры front/back и обработанного edge не обязаны образовывать один непрерывный рисунок.
- На максимальном увеличении качество проверено в desktop Metal; реальный iPhone, компрессия, потоковая загрузка LOD и live-композитор в приложении пока не проверялись и не подключались.
- Совпадение исходного шрифта требует оригинального файла шрифта или векторных текстовых контуров.
