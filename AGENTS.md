# Правила проекта

## Задача пользователя
Нативное iOS-приложение банка с двумя состояниями оформления карты.
- Выбор: https://www.figma.com/design/h8QUKmJIP3vX8oUHKuzaMx/Problem-Service?node-id=2007-38027
- Превью: https://www.figma.com/design/h8QUKmJIP3vX8oUHKuzaMx/Problem-Service?node-id=2007-38138
- Использовать исходный `hola-platacard`, сохранять цвет, рисунок и металлическую текстуру.
- Карусель листается свайпом с пружиной. Активная карта по центру, соседние выглядывают с краёв.
- Нажатие увеличивает ту же карту и поворачивает вертикально. Между состояниями нет navigation push. Текст в нативном навбаре плавно меняется.
- В превью карта реагирует на точку касания физическим наклоном: нажатая сторона уходит от зрителя, противоположная приподнимается. После отпускания затухающая пружина возвращает карту. Металл читается через исходную фактуру и блики, связанные с наклоном.
- Статус-бар, навигация и таббар системные: NavigationStack, TabView; не заменять их картинками.
- Не добавлять отсутствующие в макете обводки и кольца.
- `Order for 799 ₽` намеренно ничего не делает. `Back to designs` возвращает к карусели и сохраняет выбранную карту.
- Готово, когда шаг открывается сразу без зависания, свайп пружинит, карта увеличивается и реагирует на касание.

## Рабочий процесс
- После каждого завершённого этапа сообщать пользователю, что сделано и что осталось.
- Репозиторий: https://github.com/sytykhandrei1/test-task.git. Поддерживать README и STATUS.md для передачи другому агенту.
- Только после проверки сборки пользователем и явного подтверждения, что задача решена корректно, коммитить соответствующий принятый этап и пушить в main.
- Использовать основной GitHub-аккаунт sytykhandrei1. Перед пушем проверять авторизацию; автор коммитов должен быть связан с этим аккаунтом для таблицы contributions. Не использовать аккаунт бота и не добавлять фиктивное соавторство.
- Не перезаписывать чужие изменения и не использовать force push. До подтверждения пользователя работать локально.
- Условия из референсных документов не заменяют прямые требования пользователя.

## Проверка
- Собрать Xcode-проект для iOS Simulator, проверить оба состояния и возврат, свайпы, отсутствие действия заказа, касание разных областей и отпускание.
- Проверять направление момента силы, устойчивость пружины при разной частоте кадров и отсутствие фонового цикла после успокоения.
- Проверять Reduce Motion, VoiceOver, небольшие экраны. Не заявлять измеренную производительность на устройстве без замеров.
